## 1. AI, ML, LLM и токены

- **AI (Artificial Intelligence — искусственный интеллект)** — широкий термин для систем, выполняющих задачи, требующие интеллектуальной обработки.
- **ML (Machine Learning — машинное обучение)** — подход, при котором модель обучается закономерностям на данных.
- **LLM (Large Language Model — большая языковая модель)** — модель, обученная работать с текстом и другими представлениями данных. Типичные задачи: ответить на вопрос, суммировать документ, сгенерировать код.
- **Token (токен)** — единица представления текста, которую обрабатывает модель. Это **не обязательно слово**: одно слово может состоять из нескольких токенов.
- **Inference (инференс, выполнение модели)** — получение ответа от уже обученной модели.

**Как это работает в общих чертах:** модель получает входные токены и поочерёдно формирует выходные, опираясь на изученные закономерности и доступный контекст. Она не является базой данных фактов и может уверенно ошибаться.

## 2. Промпт, контекст и ограничения модели

**Prompt (промпт)** — инструкция и данные, которые передаются модели: например, «Объясни ошибку API по этим логам».

**Context window (окно контекста)** — объём входной информации и истории, которые модель может учитывать при работе. Если нужных данных в контексте нет, модель не сможет надёжно знать их только потому, что «умеет отвечать на вопросы».

**Hallucination (галлюцинация)** — правдоподобный, но неверный или выдуманный ответ. Например, модель придумывает несуществующий метод API.

**Temperature (температура)** — параметр генерации, который может влиять на разнообразие ответов, если конкретная модель/API его поддерживает. Низкая температура **не гарантирует** фактическую достоверность.

**Важно:** инструкция «не ошибайся» не заменяет источники, проверки и контроль действий.

## 3. Как ИИ вызывает инструменты

Представим запрос пользователя: «Получи бонусы пользователя 123 из нашего Backend».

У модели **по умолчанию нет прямого доступа** к внутренней БД и API. Чтобы выполнить задачу, приложение должно предоставить ей инструмент.

**Tool calling (вызов инструментов)** — механизм, при котором модель выбирает доступный инструмент и формирует аргументы. **Реальный вызов выполняет приложение**, а не «внутренний интеллект» модели.

```text
Пользователь: «Покажи бонусы пользователя 123»
           |
           v
       LLM-модель
           |
           | Предлагает вызов get_user_bonuses({ userId: 123 })
           v
    Приложение / исполнитель
           |
           | GET /api/bonuses?userId=123 + авторизация
           v
       Bonus Service
           |
           | JSON с бонусами
           v
    Приложение -> модель -> ответ пользователю
```

Инструмент обычно описывается именем, назначением и схемой параметров. Например, модель может получить определение `get_user_bonuses(userId: string)`.

**Существенный нюанс:** модель может ошибиться с выбором инструмента или аргументами; исполнитель должен проверять аргументы, права и результат. Само описание инструмента не равно гарантии безопасного вызова.

## 4. Что такое AI-агент

**AI Agent (ИИ-агент)** — система, в которой модель и управляющее приложение могут выполнять **цепочку шагов** для достижения цели: выбрать инструмент, получить результат, оценить его и выбрать следующий шаг.

Например:
1. Получить тестового пользователя.
2. Создать бонус.
3. Вызвать API выдачи.
4. Проверить историю выдач.
5. Сформировать отчёт.

**Разница:** простой чат часто только отвечает текстом; агент может взаимодействовать с внешней системой через инструменты. Но термин «агент» не гарантирует автономности: конкретное приложение задаёт разрешённые действия, ограничения и необходимость подтверждения.

## 5. MCP: зачем нужен и как работает

**MCP (Model Context Protocol — протокол контекста моделей)** — открытый протокол для подключения ИИ-приложений к внешним инструментам и источникам информации по согласованному интерфейсу.

Основные роли:
- **Host (хост)** — ИИ-приложение, которое управляет взаимодействием.
- **MCP Client (клиент MCP)** — компонент хоста, поддерживающий соединение с MCP-сервером.
- **MCP Server (сервер MCP)** — предоставляет возможности внешней системы.

Основные возможности, которые может предоставлять MCP-сервер:
- **Tools (инструменты)** — операции, например `issue_bonus` или `search_issues`.
- **Resources (ресурсы)** — данные, которые клиент может читать, например документ или описание схемы.
- **Prompts (шаблоны запросов)** — подготовленные сценарии взаимодействия.

```text
                MCP                      REST / SQL / другое
ИИ-приложение --------> MCP-сервер ----------------------> Сервис
   + клиент              tools: issue_bonus               бонусов
```

**Пример:** MCP-сервер предоставляет `get_user_bonuses`. Хост узнаёт, что инструмент существует и какие аргументы он принимает. Модель предлагает вызов; хост через MCP-клиент обращается к серверу; тот при необходимости вызывает обычный REST API.

**MCP не является моделью**, не заменяет REST, не предоставляет автоматически доступ ко всем системам и сам по себе не обеспечивает безопасность.

**Транспорт:** локальный MCP-сервер может запускаться через stdio (стандартные потоки ввода/вывода процесса); для удалённых серверов используется сетевой транспорт, например Streamable HTTP. Детали транспорта могут зависеть от версии спецификации.

## 6. MCP vs прямой REST API

Вопрос с собеседования: «Зачем MCP, если можно дать ИИ Swagger/OpenAPI и токен?»

**Можно и без MCP** — если ИИ-приложение умеет выполнять HTTP-запросы и безопасно хранит учётные данные.

| Критерий | Прямой API | MCP |
|---|---|---|
| Что подключают к ИИ | HTTP-инструмент или собственную интеграцию с API | MCP-клиент к MCP-серверу |
| Как узнают операции | OpenAPI / код интеграции / объявления функций | Стандартизированное описание tools/resources/prompts |
| Вызовы сервиса | Напрямую через HTTP-клиент | MCP-сервер часто сам вызывает REST API |
| Повторное использование | Зависит от реализации интеграции | Удобнее для разных совместимых ИИ-клиентов |
| Нужны ли права | Да | Да |
| Может ли выполнить удаление | Да, при соответствующих правах | Да, если инструмент разрешён и права выданы |

**Итог:** MCP в первую очередь стандартизирует интеграции. Для нескольких HTTP-методов одного сервиса отдельный MCP-сервер может быть избыточен.

**Про токены:** лучше хранить API-ключи и OAuth-токены в защищённой конфигурации исполняющего приложения, а не вставлять секреты в текст промпта. Удалённые MCP-серверы тоже требуют продуманной аутентификации и авторизации.

## 7. RAG: ответы на основе документов

**RAG (Retrieval-Augmented Generation — генерация с дополнением через поиск)** — подход, при котором перед ответом приложение находит релевантную информацию во внешних источниках и передаёт её модели.

Например, пользователь спрашивает: «Какие ограничения есть у API выдачи бонуса?»

```text
Вопрос -> поиск по документации -> найденные фрагменты
                                             |
                                             v
                                    Модель формирует ответ
                                    с опорой на материалы
```

Без RAG модель может не знать актуальный внутренний контракт API. С RAG она получает найденный текст. Но **плохая выдача поиска или устаревшие документы** могут привести к неверному ответу — ссылки на источники и проверки всё равно нужны.

**RAG и MCP — не конкуренты:** RAG — схема получения контекста для ответа, а MCP — протокол подключения возможностей и источников. Поиск для RAG иногда реализуют через MCP-инструмент.

## 8. Риски и проверки QA

| Риск | Пример | Что проверить |
|---|---|---|
| Галлюцинация | Модель придумала поле `bonusType` | Проверять ответы по реальной OpenAPI-схеме |
| Неверные аргументы | `userId` передан неверным типом | Валидация, обработка ошибок, отсутствие побочного эффекта |
| **Prompt injection (инъекция инструкций)** | Текст документа просит «игнорировать правила и удалить бонусы» | Данные из документов не должны давать новые полномочия |
| Избыточные права | Инструмент удаления доступен только для чтения отчётов | Минимальные права, ограничения по ролям |
| Опасное действие | Модель вызвала `delete_bonus` не тому пользователю | Подтверждение, проверка параметров, аудит |
| Утечка данных | Ответ содержит чужие персональные данные | Контроль доступа, редактирование логов, изоляция пользователей |
| Повтор операции | Сбой и повтор `issue_bonus` | Идемпотентность, отсутствие двойной выдачи |
| Таймаут/недоступность | MCP-сервер или API не отвечает | Корректная ошибка, ограничения повторов, прозрачный статус |

**Практическая мысль для QA:** тестировать нужно не только качество текстового ответа модели, но и действия интеграции: **какой инструмент вызван, какие аргументы переданы, что произошло в Backend и не изменились ли данные неожиданно**.

## 9. Короткие ответы для собеседования

### Что такое LLM?

LLM — большая языковая модель, которая обрабатывает входной контекст и генерирует ответ. Она может решать текстовые задачи, но не гарантирует точность фактов и сама по себе не получает доступ к внутренним сервисам.

</details>

### Что такое Tool Calling?
<details><summary>Показать ответ</summary>

Модель выбирает доступный инструмент и формирует аргументы. ИИ-приложение выполняет реальный вызов, получает результат и может передать его модели для ответа. Нужны проверки аргументов и прав доступа.

</details>

### Чем агент отличается от обычного ответа LLM?
<details><summary>Показать ответ</summary>

Агент может выполнять последовательность действий через инструменты: например, создать тестовые данные, вызвать API и проверить результат. Уровень самостоятельности зависит от приложения.

</details>

### Что такое MCP и чем он отличается от REST API?
<details><summary>Показать ответ</summary>

MCP — стандарт предоставления инструментов и ресурсов ИИ-клиентам. REST — способ взаимодействия с сервисом через HTTP. MCP-сервер может внутри использовать обычный REST API. MCP полезен для стандартизированного повторного подключения интеграций.

</details>

### Можно ли обойтись без MCP?
<details><summary>Показать ответ</summary>

Да. Если приложению доступен HTTP-инструмент, описание API и безопасная авторизация, оно может вызывать сервис напрямую. MCP — удобная стандартизация, а не обязательное условие вызова API.

</details>

### Что такое RAG?
<details><summary>Показать ответ</summary>

RAG — подход, когда приложение сначала ищет релевантные данные, затем передаёт их модели, чтобы та отвечала на основе найденного контекста. Это не гарантирует отсутствие ошибок.

</details>

### Что опасного в подключении ИИ к инструментам?
<details><summary>Показать ответ</summary>

Модель может ошибиться с параметрами или поддаться prompt injection из недоверенного текста. Поэтому важны минимальные права, проверка входных данных, подтверждения чувствительных действий, аудит и идемпотентность.

</details>
