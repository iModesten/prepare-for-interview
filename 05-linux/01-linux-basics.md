# Часть 1. Основы Linux

## 1. Что такое Linux?

**Linux** — ядро операционной системы.

В повседневной речи под Linux обычно подразумевают полноценную операционную систему, состоящую из:

- Ядра Linux.
- Системных библиотек.
- Системных утилит.
- Командной оболочки.
- Системы управления пакетами.
- Дополнительного программного обеспечения.

Такие системы обычно называют дистрибутивами Linux.

### Популярные дистрибутивы

- Ubuntu.
- Debian.
- Fedora.
- Red Hat Enterprise Linux.
- Rocky Linux.
- AlmaLinux.
- Alpine Linux.

### Где Linux встречается в QA?

- Backend-серверы.
- Тестовые стенды.
- CI/CD.
- Docker-контейнеры.
- Kubernetes.
- Системы мониторинга.
- Базы данных.
- Сервисы обработки сообщений.

### Краткий ответ для собеседования

> Linux — ядро операционной системы, на основе которого создаются различные дистрибутивы. В Backend QA Linux используется для работы с тестовыми стендами, запуска приложений, анализа логов, проверки сетевых соединений, конфигураций и диагностики ошибок.

## 2. Terminal, Shell и Bash

Эти понятия часто смешивают.

### Terminal

Приложение, через которое пользователь взаимодействует с командной строкой.

Например:

- GNOME Terminal.
- Konsole.
- Windows Terminal.
- iTerm2.

### Shell

Командный интерпретатор, который принимает и выполняет команды.

Примеры:

- Bash.
- Zsh.
- Fish.
- Dash.

### Bash

**Bash (Bourne Again Shell)** — распространённая командная оболочка Linux.

Она позволяет:

- Выполнять команды.
- Работать с файлами.
- Использовать переменные.
- Объединять команды.
- Писать скрипты.
- Автоматизировать задачи.

### Пример

```bash
pwd
ls
cd /tmp
```

Пользователь вводит команды в терминале, а оболочка интерпретирует и выполняет их.

### Важный нюанс

Не все команды являются отдельными исполняемыми программами.

Например, `cd` обычно является встроенной командой Shell, поскольку она должна изменять рабочую директорию текущей оболочки.

---

## 3. Структура Linux-команды

Общий вид:

```bash
command [options] [arguments]
```

Например:

```bash
ls -lah /var/log
```

Здесь:

- `ls` — команда.
- `-lah` — опции.
- `/var/log` — аргумент.

### Короткие опции

```bash
ls -l -a -h
```

Часто их можно объединять:

```bash
ls -lah
```

### Длинные опции

```bash
ls --all
```

### Важный нюанс

Синтаксис и доступные опции зависят от конкретной команды и её реализации.

Например, утилиты GNU Linux могут поддерживать опции, которых нет в аналогах macOS или BusyBox.

---

## 4. Как получить помощь по команде?

### --help

```bash
ls --help
```

Показывает краткую справку, если команда поддерживает эту опцию.

### man

```bash
man ls
```

Открывает руководство по команде.

Для выхода из `man` обычно используется:

```text
q
```

### type

```bash
type cd
```

Позволяет узнать, как оболочка интерпретирует команду: встроенная команда, функция, псевдоним или исполняемый файл.

### command -v

```bash
command -v python3
```

Помогает определить, доступна ли команда и как она разрешается текущей оболочкой.

### Для QA

Если на сервере неизвестна какая-то утилита, не обязательно сразу искать инструкцию в интернете.

Можно начать с:

```bash
command --help
man command
```

где `command` — имя нужной утилиты, если она поддерживает соответствующий способ справки.

# Часть 2. Файловая система

## 5. Структура файловой системы Linux

В Linux используется единая иерархия файловой системы.

Её верхняя точка — корневая директория:

```text
/
```

В отличие от Windows, здесь нет обязательной модели отдельных корней `C:\`, `D:\` и так далее.

### Упрощённая структура

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
│   └── qa
├── opt
├── proc
├── root
├── run
├── srv
├── tmp
├── usr
│   ├── bin
│   └── lib
└── var
    ├── lib
    └── log
```

На современных дистрибутивах некоторые директории, например `/bin`, могут быть символическими ссылками на соответствующие директории внутри `/usr`.

### Основные директории

| Директория | Назначение |
|---|---|
| `/` | Корень файловой системы |
| `/home` | Домашние директории обычных пользователей |
| `/root` | Домашняя директория пользователя root |
| `/etc` | Системные конфигурационные файлы |
| `/var/log` | Файлы логов, если приложение их использует |
| `/var/lib` | Изменяемые данные приложений и сервисов |
| `/tmp` | Временные файлы |
| `/usr/bin` | Многие пользовательские команды |
| `/opt` | Дополнительное установленное ПО |
| `/proc` | Виртуальная файловая система с информацией о процессах и ядре |
| `/dev` | Файлы устройств |
| `/run` | Runtime-данные работающей системы |

### Что особенно важно для Backend QA?

**`/etc`**

Здесь часто находятся конфигурации сервисов.

Например:

```text
/etc/nginx/nginx.conf
```

**`/var/log`**

Может содержать системные и прикладные логи.

**`/var/lib`**

Часто используется для постоянного состояния сервисов.

**`/tmp`**

Подходит для временных файлов, но содержимое может очищаться системой.

**`/proc`**

Позволяет получать информацию о работающих процессах и системе.

### Важный нюанс

Не каждое приложение пишет логи непосредственно в `/var/log`.

В современных системах логи также могут поступать в:

- systemd journal.
- stdout/stderr контейнера.
- Централизованную систему логирования.

## 6. Абсолютный и относительный путь

### Absolute Path

Абсолютный путь начинается с `/`.

Например:

```bash
/var/log/app.log
```

Он указывает расположение относительно корня файловой системы.

### Relative Path

Относительный путь рассчитывается от текущей рабочей директории.

Например:

```bash
logs/app.log
```

Если текущая директория:

```text
/home/qa/project
```

Тогда относительный путь обозначает:

```text
/home/qa/project/logs/app.log
```

### Специальные обозначения

| Обозначение | Значение |
|---|---|
| `/` | Корневая директория |
| `.` | Текущая директория |
| `..` | Родительская директория |
| `~` | Домашняя директория пользователя в контексте расширения Shell |
| `-` | Предыдущая директория в команде cd |

### Пример

```bash
cd /home/qa/project
cd ..
```

После второй команды пользователь окажется в:

```text
/home/qa
```

# Часть 3. Навигация

## 7. pwd — текущая директория

**pwd (Print Working Directory)** показывает текущую рабочую директорию.

```bash
pwd
```

Пример результата:

```text
/home/qa/project
```

### Когда полезно QA?

Когда нужно убедиться, что команда выполняется в правильной директории.

Особенно важно перед операциями копирования, перемещения или удаления файлов.

### Дополнительный нюанс

В некоторых Shell есть различие между логическим и физическим путём, например при переходах через символические ссылки.

В Bash могут использоваться:

```bash
pwd -L
pwd -P
```

`-P` показывает физический путь с разрешением символических ссылок в компонентах пути.

---

## 8. ls — содержимое директории

**ls (List)** показывает файлы и директории.

```bash
ls
```

### Подробный вывод

```bash
ls -l
```

Пример:

```text
-rw-r--r-- 1 qa developers 1024 Oct  9 12:00 app.log
drwxr-xr-x 2 qa developers 4096 Oct  9 12:00 configs
```

### Показать скрытые файлы

```bash
ls -a
```

В Linux имена файлов, начинающиеся с точки, обычно скрыты при обычном выводе `ls`.

Например:

```text
.env
.gitignore
.bashrc
```

### Размеры в удобном виде

```bash
ls -lh
```

### Частая комбинация

```bash
ls -lah
```

Это одна из самых полезных команд при работе с сервером.

### Посмотреть конкретную директорию

```bash
ls -lah /var/log
```

### Посмотреть сведения о самой директории

```bash
ls -ld /var/log
```

**Разница:** `ls -l /var/log` обычно перечисляет содержимое директории, а `ls -ld /var/log` показывает сведения о самой директории.

---

## 9. cd — смена директории

**cd (Change Directory)** меняет текущую рабочую директорию Shell.

### Перейти в директорию

```bash
cd /var/log
```

### Перейти в домашнюю директорию

```bash
cd
```

Или:

```bash
cd ~
```

### На уровень выше

```bash
cd ..
```

### Вернуться в предыдущую директорию

```bash
cd -
```

### Перейти по относительному пути

```bash
cd projects/backend
```

### Пример

```bash
pwd
```

```text
/home/qa
```

```bash
cd projects/backend
pwd
```

```text
/home/qa/projects/backend
```

### Типичные ошибки

**No such file or directory**

Директория не существует по указанному пути.

**Permission denied**

Недостаточно прав для перехода в директорию или один из компонентов пути.

**Not a directory**

В одном из компонентов пути ожидается директория, но обнаружен объект другого типа.

# Часть 4. Работа с файлами и директориями

## 10. mkdir — создание директорий

**mkdir (Make Directory)** создаёт директорию.

```bash
mkdir logs
```

Создать вложенную структуру:

```bash
mkdir -p project/config/dev
```

### Что делает -p?

Позволяет создать отсутствующие родительские директории.

Также не считает ошибкой существование целевой директории.

### Пример

```bash
mkdir -p ~/qa-linux-practice/logs
```

Создаёт директорию для учебных примеров.

---

## 11. touch — создание файла и обновление времени

**touch** обновляет временные метки файла.

Если файла нет, команда обычно создаёт пустой файл.

```bash
touch app.log
```

### Пример

```bash
touch test-data.json
```

### Важный нюанс

Основное назначение touch — работа с временными метками, а не создание текстового содержимого.

Чтобы записать данные в файл, используют другие команды или текстовые редакторы.

---

## 12. cp — копирование файлов

**cp (Copy)** копирует файлы и директории.

### Копирование файла

```bash
cp config.json config-backup.json
```

### Копирование в другую директорию

```bash
cp config.json backups/
```

### Копирование директории

```bash
cp -r configs configs-backup
```

### Интерактивное подтверждение перезаписи

```bash
cp -i config.json backups/
```

### Для QA

Полезно перед изменением конфигурационного файла:

```bash
cp app.conf app.conf.backup
```

Но на рабочих серверах любые изменения конфигураций нужно выполнять только с соответствующими правами и пониманием процесса развёртывания.

### Важный нюанс

Обычное копирование не всегда сохраняет все метаданные исходного файла. Для этого существуют специальные опции, например `-p` и `-a` в GNU Coreutils.

---

## 13. mv — перемещение и переименование

**mv (Move)** используется для перемещения и переименования.

### Переименовать

```bash
mv old-name.txt new-name.txt
```

### Переместить

```bash
mv app.log logs/
```

### Запрашивать подтверждение при перезаписи

```bash
mv -i config.json backups/
```

### Важный нюанс

`mv` может перезаписать существующий файл в зависимости от аргументов и настроек команды.

Поэтому важно проверять целевой путь.

---

## 14. rm — удаление файлов

**rm (Remove)** удаляет файлы.

```bash
rm temporary.txt
```

### Подтверждение удаления

```bash
rm -i temporary.txt
```

### Удаление директории с содержимым

```bash
rm -r temporary-directory
```

### Важное предупреждение

Команда `rm` обычно не перемещает данные в корзину.

На сервере удаление может оказаться необратимым без резервной копии.

Особенно опасны рекурсивные команды удаления с флагами, отключающими дополнительные проверки.

### Для QA

При работе с тестовыми данными лучше:

1. Проверить текущую директорию через `pwd`.
2. Посмотреть содержимое через `ls`.
3. Убедиться в целевом пути.
4. По возможности использовать интерактивное подтверждение.

---

## 15. rmdir — удаление пустой директории

**rmdir** удаляет пустую директорию.

```bash
rmdir empty-directory
```

Если внутри есть файлы, команда обычно завершится ошибкой.

Для учебных задач это более безопасный вариант удаления пустой директории, чем рекурсивное удаление.

## 16. cat — просмотр содержимого файла

**cat** выводит содержимое файла.

```bash
cat config.json
```

### Пример файла

```json
{
  "database": {
    "host": "postgres",
    "port": 5432
  }
}
```

Команда:

```bash
cat config.json
```

Выведет этот JSON в терминал.

### Когда полезно?

- Быстро посмотреть конфигурацию.
- Проверить содержимое небольшого файла.
- Прочитать тестовые данные.
- Проверить формат JSON или текста.

### Когда не стоит использовать cat?

Для очень больших логов.

В таком случае вывод может оказаться огромным и неудобным.

Лучше использовать:

- less.
- head.
- tail.
- grep.

Их подробно рассмотрим в следующем файле.

## 17. less — постраничный просмотр

**less** позволяет удобно просматривать длинные файлы.

```bash
less app.log
```

### Основные клавиши

| Клавиша | Действие |
|---|---|
| `Space` | Вперёд на страницу |
| `b` | Назад на страницу |
| `/text` | Поиск текста |
| `n` | Следующее совпадение |
| `N` | Предыдущее совпадение |
| `g` | Начало файла |
| `G` | Конец файла |
| `q` | Выход |

### Для Backend QA

Если есть большой файл логов:

```bash
less /var/log/my-service/app.log
```

Можно изучать его без вывода всех строк сразу.

Путь здесь условный — фактическое расположение логов зависит от конфигурации сервиса.

## 18. head и tail

### head

Показать первые строки файла:

```bash
head app.log
```

Первые 20 строк:

```bash
head -n 20 app.log
```

### tail

Показать последние строки файла:

```bash
tail app.log
```

Последние 50 строк:

```bash
tail -n 50 app.log
```

### tail -f

Следить за появлением новых строк:

```bash
tail -f app.log
```

Это очень полезная команда при тестировании Backend.

Например:

1. Открыть терминал с `tail -f`.
2. Вызвать API.
3. Наблюдать появление новых логов.
4. Проверить ошибку или ожидаемое событие.

Остановить просмотр:

```text
Ctrl + C
```

### Важный нюанс

При ротации логов `tail -f` и `tail -F` ведут себя по-разному.

На GNU Linux `tail -F` удобен для отслеживания файла по имени, если он удаляется и создаётся заново при ротации.

# Часть 5. Как Linux определяет тип файла?

## 19. Типы файлов

В Linux существуют разные типы файловых объектов:

- Обычные файлы.
- Директории.
- Символические ссылки.
- Сокеты.
- Каналы FIFO.
- Символьные устройства.
- Блочные устройства.

### Вывод ls -l

Пример:

```text
-rw-r--r-- 1 qa qa 1024 Oct  9 12:00 app.log
drwxr-xr-x 2 qa qa 4096 Oct  9 12:00 configs
lrwxrwxrwx 1 qa qa   15 Oct  9 12:00 current -> releases/v2
```

Первый символ обозначает тип:

| Символ | Тип |
|---|---|
| `-` | Обычный файл |
| `d` | Директория |
| `l` | Символическая ссылка |
| `s` | Сокет |
| `p` | FIFO |
| `c` | Символьное устройство |
| `b` | Блочное устройство |

### file

Команда `file` помогает определить тип содержимого:

```bash
file app.log
```

```bash
file application.jar
```

### stat

Показывает подробную информацию о файле:

```bash
stat app.log
```

Например:

- Размер.
- Владелец.
- Группа.
- Права.
- Временные метки.
- Inode.

## 20. Символические и жёсткие ссылки

### Symbolic Link

Символическая ссылка указывает на другой путь.

Создать:

```bash
ln -s releases/v2 current
```

Теперь `current` указывает на `releases/v2`.

### Где используются?

В системах развёртывания:

```text
/app/releases/v1
/app/releases/v2
/app/current -> releases/v2
```

Приложение может обращаться к `current`, а процесс деплоя — менять целевую версию.

### Проверить ссылку

```bash
ls -l current
```

```bash
readlink current
```

На GNU Linux получить разрешённый путь можно через:

```bash
readlink -f current
```

### Hard Link

Жёсткая ссылка — дополнительное имя для того же inode файла в файловой системе.

Пример:

```bash
ln original.txt hardlink.txt
```

### Отличия

| Symbolic Link | Hard Link |
|---|---|
| Указывает на путь | Ссылается на тот же inode |
| Может указывать на директорию | Обычно не создаётся пользователями для директорий |
| Может стать битой ссылкой | Продолжает ссылаться на данные после удаления другого имени |
| Может указывать на объект в другой файловой системе | Обычно не может пересекать файловые системы |

### Для интервью

Достаточно понимать, что символическая ссылка похожа на перенаправление к другому пути, а hard link — ещё одно имя того же файла.

# Часть 6. Пользователи и права доступа

## 21. Пользователи и группы Linux

Linux — многопользовательская система.

У процессов и файлов существуют идентификаторы пользователей и групп.

### whoami

Показать имя текущего эффективного пользователя:

```bash
whoami
```

### id

Показать сведения об идентификаторах пользователя и групп:

```bash
id
```

Пример:

```text
uid=1001(qa) gid=1001(qa) groups=1001(qa),1002(developers)
```

### groups

Показать группы пользователя:

```bash
groups
```

### Зачем нужны группы?

Чтобы предоставлять нескольким пользователям общий доступ к файлам и директориям.

Например, пользователи из группы `developers` могут иметь доступ к конфигурациям тестового приложения.

---

## 22. Как читать права доступа?

Одна из важнейших тем Linux для собеседования.

Пример:

```bash
ls -l app.log
```

Результат:

```text id="4modqb"
-rw-r----- 1 qa developers 1024 Oct  9 12:00 app.log
```

Разберём:

```text id="zplp5p"
- rw- r-- ---
│ │   │   │
│ │   │   └── Others
│ │   └────── Group
│ └────────── Owner
└──────────── Тип файла
```

### Три категории пользователей

**Owner**

Владелец файла.

**Group**

Пользователи, для которых применяются групповые права.

**Others**

Остальные пользователи.

### Три основных разрешения

| Символ | Значение для обычного файла |
|---|---|
| `r` | Read |
| `w` | Write |
| `x` | Execute |

Пример:

```text id="6p68yg"
rw-
```

Означает:

- Читать разрешено.
- Изменять разрешено.
- Выполнять как программу — нет.

### Пример

```text id="laskx3"
-rw-r-----
```

Owner: `rw-`

Group: `r--`

Others: `---`

Владелец может читать и изменять файл.

Участники подходящей группы могут читать.

Остальные не получают доступ через эти базовые биты.

---

## 23. Права на директории

Это очень важный нюанс.

Права директорий отличаются по смыслу от прав обычных файлов.

| Право | Значение для директории |
|---|---|
| `r` | Читать список имён внутри |
| `w` | Изменять записи директории при наличии необходимых дополнительных прав |
| `x` | Проходить через директорию, обращаться к известным именам внутри |

### Пример

```text id="6epkwl"
drwxr-x---
```

Owner может:

- Просматривать имена файлов.
- Создавать и удалять записи при соответствующих условиях.
- Проходить внутрь.

Group может:

- Просматривать имена.
- Проходить внутрь.

Others не имеют соответствующих базовых прав.

### Почему важно право x на директорию?

Потому что без него пользователь не сможет нормально пройти через директорию даже к файлу, на который у него есть права.

### Практический пример

Файл имеет:

```text id="v7z90b"
-rw-r--r-- app.log
```

Но родительская директория:

```text id="un6w5p"
drwx------ logs
```

Другой пользователь не сможет прочитать `logs/app.log`, несмотря на `r--` для Others у самого файла.

**Причина:** отсутствует право прохода через директорию.

## 24. Числовая запись прав: chmod

Права часто обозначают числами.

| Право | Число |
|---|---|
| Read | 4 |
| Write | 2 |
| Execute | 1 |

Каждая тройка прав вычисляется суммой.

### Примеры

**7 = 4 + 2 + 1**

```text id="mrvoql"
rwx
```

**6 = 4 + 2**

```text id="fcpg92"
rw-
```

**5 = 4 + 1**

```text id="gj3ve1"
r-x
```

**4**

```text id="bm7nd2"
r--
```

### chmod 755

```bash
chmod 755 script.sh
```

Результат:

```text id="qd5d0p"
rwxr-xr-x
```

- Owner: 7 — rwx.
- Group: 5 — r-x.
- Others: 5 — r-x.

### chmod 644

```bash
chmod 644 config.json
```

Результат:

```text id="84qry5"
rw-r--r--
```

### chmod 600

```bash
chmod 600 private.txt
```

Результат:

```text id="nf2nsm"
rw-------
```

### Частые значения

| Значение | Права | Типичное применение |
|---|---|---|
| 600 | rw------- | Приватный файл |
| 640 | rw-r----- | Файл для владельца и группы |
| 644 | rw-r--r-- | Обычный читаемый файл |
| 700 | rwx------ | Приватная директория или исполняемый файл |
| 755 | rwxr-xr-x | Директория или исполняемый файл |
| 777 | rwxrwxrwx | Всем доступны все базовые права |

### Важно

Не стоит решать ошибки доступа командой:

```bash
chmod 777 file
```

Это может открыть ненужные права всем пользователям.

Сначала следует выяснить, какой пользователь или сервис должен иметь доступ и какие именно разрешения нужны.

---

## 25. Символьная запись chmod

Права можно изменять не только числами.

### Добавить Execute владельцу

```bash
chmod u+x script.sh
```

### Убрать Write у группы

```bash
chmod g-w config.json
```

### Убрать доступ у Others

```bash
chmod o-rwx private.txt
```

### Установить владельцу Read и Write

```bash
chmod u=rw config.json
```

Обозначения:

| Символ | Значение |
|---|---|
| `u` | User / Owner |
| `g` | Group |
| `o` | Others |
| `a` | All |
| `+` | Добавить |
| `-` | Убрать |
| `=` | Установить |

### Что лучше знать для интервью?

Оба варианта:

```bash
chmod 755 script.sh
```

И:

```bash
chmod u+x script.sh
```

## 26. chown и chgrp

### chown

Изменяет владельца файла.

Например:

```bash
sudo chown qa app.log
```

Установить владельца и группу:

```bash
sudo chown qa:developers app.log
```

### chgrp

Изменяет группу файла:

```bash
chgrp developers app.log
```

Изменение владельца обычно требует соответствующих привилегий.

### Что проверить при Permission denied?

1. Кто запускает приложение?
2. Кто является владельцем файла?
3. Какая группа назначена?
4. Какие права у самого файла?
5. Какие права у родительских директорий?
6. Нет ли дополнительных ограничений ACL, SELinux, AppArmor или файловой системы?

### Важно

Базовые Unix permissions — не единственный механизм контроля доступа Linux.

Могут использоваться ACL и дополнительные механизмы безопасности.

## 27. sudo и root

**root** — привилегированный пользователь Linux.

**sudo** позволяет выполнить команду с правами другого пользователя, обычно root, если это разрешено настройками системы.

Пример:

```bash
sudo systemctl status nginx
```

### Для чего это нужно?

Например, для просмотра информации или управления системными сервисами, если текущий пользователь не имеет необходимых прав.

### Почему sudo нужно использовать осторожно?

Потому что привилегированная команда может:

- Изменять системные настройки.
- Удалять важные файлы.
- Изменять владельцев и права.
- Останавливать сервисы.

### Senior QA-подход

Не нужно автоматически запускать любую неработающую команду через sudo.

Сначала необходимо понять причину отказа и определить минимальные достаточные права.

---

## 28. umask — права по умолчанию

**umask** влияет на права новых файлов и директорий.

Посмотреть текущую маску:

```bash
umask
```

Пример:

```text id="keig7r"
0022
```

При типичном umask 022 новые обычные файлы часто получают права:

```text id="tuxt06"
644
```

Новые директории:

```text id="4spy3d"
755
```

### Почему не 777 для обычных файлов?

Потому что обычные файлы обычно создаются с базовыми правами без Execute.

Типичные базовые значения до применения umask:

```text id="cyccdg"
Files:       666
Directories: 777
```

Но итог также зависит от способа создания файла, файловой системы и других механизмов прав доступа.

### Для интервью

Достаточно знать, что umask ограничивает права, выдаваемые новым файлам и директориям по умолчанию.

# Часть 7. Переменные окружения

## 29. Что такое Environment Variables?

**Environment Variables** — переменные окружения, передаваемые процессам и используемые для конфигурации программ.

Примеры:

```text id="a4abno"
HOME
PATH
USER
LANG
APP_ENV
DATABASE_HOST
```

### Посмотреть значение переменной

```bash
echo "$HOME"
```

```bash
echo "$PATH"
```

### Посмотреть переменные окружения

```bash
printenv
```

### Посмотреть одну переменную

```bash
printenv PATH
```

### Создать переменную окружения для дочерних процессов

```bash
export APP_ENV=test
```

Проверить:

```bash
echo "$APP_ENV"
```

### Важный нюанс

Такая переменная действует в текущем окружении Shell и наследуется запускаемыми из него дочерними процессами.

Она не становится автоматически постоянной настройкой всей операционной системы.

## 30. Что такое PATH?

**PATH** — переменная окружения, содержащая список директорий, в которых Shell ищет исполняемые команды.

Пример:

```bash
echo "$PATH"
```

Результат может выглядеть так:

```text id="5wj3kk"
/usr/local/bin:/usr/bin:/bin
```

Когда пользователь вводит:

```bash
python3
```

Shell ищет подходящую команду в директориях PATH.

### Почему ./script.sh отличается от script.sh?

Допустим, скрипт находится в текущей директории.

```bash
script.sh
```

Может вернуть:

```text id="jjjg9i"
command not found
```

Если текущая директория не входит в PATH.

Но:

```bash
./script.sh
```

Явно указывает путь к скрипту.

Для прямого выполнения также необходимы соответствующие права и корректный формат исполняемого файла.

### Важный нюанс

Добавлять текущую директорию в PATH без необходимости небезопасно: это может привести к запуску неожиданного исполняемого файла.

## 31. Кавычки в Shell

При работе с командами важно понимать, как Shell интерпретирует строки.

### Без кавычек

```bash
echo $HOME
```

Значение переменной подставляется оболочкой.

### Двойные кавычки

```bash
echo "$HOME"
```

Значение переменной также подставляется, но сохраняется как один аргумент без обычного разбиения по пробелам.

### Одинарные кавычки

```bash
echo '$HOME'
```

Результат:

```text id="8ifpc0"
$HOME
```

Переменная не подставляется.

### Почему это важно?

Предположим, файл называется:

```text id="hd9e8p"
test data.json
```

Команда:

```bash
cat test data.json
```

Будет интерпретирована как два отдельных имени файла.

Нужно:

```bash
cat "test data.json"
```

### Для QA

Ошибки с кавычками часто встречаются:

- В Bash-скриптах.
- В CI/CD.
- При передаче JSON.
- При работе с путями.
- При передаче переменных окружения.

---

## 32. Wildcards и Globbing

Shell поддерживает шаблоны имён файлов.

### *

```bash
ls *.log
```

Показать файлы с окончанием `.log` в текущей директории.

### ?

```bash
ls file?.txt
```

Может соответствовать:

```text id="s418oq"
file1.txt
fileA.txt
```

### [...]

```bash
ls file[12].txt
```

Соответствует:

```text id="ahqwnr"
file1.txt
file2.txt
```

### Важный нюанс

В Bash `*` по умолчанию не включает файлы, начинающиеся с точки, в обычное сопоставление имён.

Также поведение unmatched glob зависит от настроек Shell.

### Осторожность

Перед использованием wildcard с удалением или массовым изменением файлов нужно убедиться, какие именно пути соответствуют шаблону.

## 34. Как посмотреть свободное место?

Показывает использование пространства файловых систем.



### du

Показывает дисковое пространство, используемое файлами и директориями.

Это более продвинутый сценарий диагностики.

## 36. Сценарий: Permission denied

Приложение пытается прочитать:

```text id="kzvrq5"
/opt/my-service/config/application.yaml
```

И получает:

```text id="sqglyd"
Permission denied
```

### Порядок диагностики

**1. Узнать пользователя**

```bash
whoami
```

**2. Проверить файл**

```bash
ls -l /opt/my-service/config/application.yaml
```

**3. Проверить директории**

```bash
ls -ld /opt
ls -ld /opt/my-service
ls -ld /opt/my-service/config
```

**4. Проверить группы**

```bash
id
```

**5. При необходимости проверить весь путь**

На Linux может быть доступна команда:

```bash
namei -l /opt/my-service/config/application.yaml
```

Она помогает увидеть права отдельных компонентов пути.

### Возможные причины

- Нет Read на файле.
- Нет Execute на родительской директории.
- Неправильный владелец.
- Неправильная группа.
- ACL запрещает доступ.
- SELinux или AppArmor ограничивает операцию.
- Файловая система или mount configuration накладывает ограничения.

### Правильный подход

Не начинать с `chmod 777`.

Сначала установить, какой пользователь запускает приложение и каких минимальных прав ему не хватает.

## 39. Сценарий: посмотреть логи после API-запроса

Допустим, приложение пишет в файл:

### Посмотреть последние строки

```bash
tail -n 50 /var/log/my-service/app.log
```

### Следить за логом

```bash
tail -f /var/log/my-service/app.log
```

### Последовательность QA

1. Открыть лог.

4. Проверить статус выполнения.
5. Зафиксировать ошибку или Request ID.

На практике для больших файлов и централизованных логов удобнее использовать фильтрацию и инструменты поиска.

## 40. Как работать с сервером через SSH?

**SSH (Secure Shell)** — протокол безопасного удалённого доступа.

Типичный вызов:

```bash
ssh qa@test-server.example.com
```

Где:

- `qa` — пользователь.

Пользователь получает доступ к удалённой командной оболочке в пределах предоставленных прав.

- Проверить hostname.
- Не изменять конфигурацию без необходимости.
- Не выполнять опасные команды на production.

# Часть 10. Вопросы для собеседования

## 41. Что такое Linux?

Linux — ядро операционной системы. На его основе создаются различные дистрибутивы.

## 42. Чем Terminal отличается от Shell?

Terminal предоставляет интерфейс для ввода и вывода, Shell интерпретирует команды.

## 43. Что такое Bash?

Командная оболочка, позволяющая выполнять команды и скрипты.

## 44. Как узнать текущую директорию?

```bash
pwd
```

## 45. Как посмотреть скрытые файлы?

```bash
ls -a
```

## 46. Как перейти в домашнюю директорию?

```bash
cd
```

Или:

```bash
cd ~
```

## 47. Как создать несколько вложенных директорий?

```bash
mkdir -p a/b/c
```

## 48. Чем cp отличается от mv?

cp копирует файлы, mv перемещает или переименовывает.

## 49. Как посмотреть последние 100 строк лога?

```bash
tail -n 100 app.log
```

## 50. Как следить за логом в реальном времени?

```bash
tail -f app.log
```

## 51. Как узнать владельца и права файла?

```bash
ls -l file.txt
```

Или:

```bash
stat file.txt
```

## 52. Что означает chmod 755?

Owner имеет rwx, Group и Others — r-x.

## 53. Что означает chmod 644?

Owner имеет rw-, Group и Others — r--.

## 54. Чем права на директорию отличаются от прав на файл?

Для директории Execute означает право прохода и поиска имён, Read — получение списка имён, Write — изменение записей директории при соблюдении других условий.

## 55. Почему файл с правами 644 может быть недоступен?

Например, из-за отсутствия Execute на родительской директории или дополнительных ограничений безопасности.

## 56. Что делает sudo?

Запускает команду с правами другого пользователя в рамках разрешённой конфигурации, обычно с привилегиями root.

## 57. Что такое PATH?

Переменная окружения со списком директорий для поиска исполняемых команд.

## 58. Чем абсолютный путь отличается от относительного?

Абсолютный начинается с корня `/`, относительный определяется от текущей рабочей директории.

## 59. Чем Symbolic Link отличается от Hard Link?

Symbolic Link указывает на путь. Hard Link — дополнительное имя того же inode файла.

## 60. Как узнать свободное место на сервере?

```bash
df -h
```

Для объёма конкретной директории:

```bash
du -sh directory
```

# Частые ошибки на собеседовании

**Ошибка:** «Linux — это только Ubuntu».

Правильно: Ubuntu — один из дистрибутивов Linux.

**Ошибка:** «Terminal и Bash — одно и то же».

Правильно: Terminal — интерфейс, Bash — командная оболочка.

**Ошибка:** «chmod 755 означает, что все могут изменять файл».

Правильно: Write имеет только Owner. Group и Others получают Read и Execute.

**Ошибка:** «Если на файле есть Read, его всегда можно прочитать».

Правильно: для доступа к файлу нужны соответствующие разрешения на компонентах пути.

**Ошибка:** «chmod 777 — нормальный способ исправить Permission denied».

Правильно: нужно определить необходимого пользователя и предоставить минимальные достаточные права.

**Ошибка:** «rm перемещает файл в корзину».

Правильно: обычное удаление через rm не использует корзину.

**Ошибка:** «Переменная export автоматически сохраняется после перезагрузки».

Правильно: переменная обычно существует только в соответствующем окружении Shell и наследуется его дочерними процессами.

**Ошибка:** «Все Linux-системы имеют одинаковые пути и команды».

Правильно: дистрибутивы, контейнерные образы и используемые утилиты могут различаться.

```bash
mkdir -p ~/qa-linux-practice/logs
```

```bash
pwd
```

```bash
ls -l config/application.yaml
```

Ожидаемый базовый набор прав:

```text id="p5fbhl"
-rw-r-----
```

```bash
chmod 644 config/application.yaml
```

```bash
id

```

